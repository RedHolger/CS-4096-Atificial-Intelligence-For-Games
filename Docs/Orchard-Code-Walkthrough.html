Step by step

Card number = the order the code runs: start, loop, world, player, movement, then each AI, then the screen and testing.
1

Boot: from Play to game

OrchardGame.cs · OrchardBoot, SpriteLoader
  • The [RuntimeInitializeOnLoadMethod] attribute runs OrchardBoot.Boot() by itself as soon as a scene loads, in any scene.
  • It creates one GameObject and adds OrchardGame to it. If one already exists, it does nothing.
  • Awake() sets 60 fps and the cameras. Start() loads sprites, makes the renderer, UI and rain, then builds the map and the characters.
  • SpriteLoader reads PNG bytes from Resources/OrchardSprites and uses FilterMode.Point so the pixel art stays sharp.
// starts the game automatically when you press play
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
static void Boot() {
    if (started) return;  started = true;
    if (Object.FindAnyObjectByType<OrchardGame>() != null) return;
    new GameObject("Orchard of the Last Season").AddComponent<OrchardGame>();
}

Core: grid, types, helpers

Core.cs · C, Pos, Cell, Mover, U
  • C holds all constants in one place: GW=24, GH=16, CELL=44, TREE_HP=70, NIGHT_LEN=60, TOTAL_NIGHTS=13.
  • Pos (x, y in pixels) → Mover (adds vx, vy, r) → Farmer, Pip, Thistle and Enemy all build on it (inheritance).
  • Cell is a struct for one grid cell (cx, cy). U.w2c turns a pixel into a cell; U.cc gives the centre of a cell.
  • U.groundBlocked: a hill or bush is a wall for ground enemies. U.R() is the single random source, so tests can set its seed.
Pixel ↔ cell
cx=⌊x44⌋xcenter=44·cx+22
Board = 24 × 16 cells = 1056 × 704 px world.

Every frame: Update()

OrchardGame.cs · Update, UpdateGame
  • dt is capped at 0.033 s, so a lag spike cannot make anything jump through a wall.
  • In Phase.Play it calls UpdateGame(dt); in Phase.Transition only the timer runs (sunrise/sunset).
  • The order is fixed: spawn queue → farmer → Pip → Thistle → enemies → pack bites → remove the dead → fruit → trees.
  • Then every frame it renders and runs the UI Tick, even when the game is paused.
void UpdateGame(double dt) {
    nightTime += dt;
    while (spawnQueue.Count > 0 && spawnQueue[0].t <= nightTime) Fire(...);
    farmer.update(dt);  pip.update(dt);  thistle.update(dt);
    // reset pack flags, then every enemy thinks + moves
    for (int i = 0; i < enemies.Count; i++) enemies[i].update(dt);
    PackBites(pip, dt);  PackBites(thistle, dt);
    ...  // fruit falls -> bait, trees flash, win/lose check
}

Night flow and waves

OrchardGame.cs · StartNight, BuildWave, Fire, EndNight
  • StartNight: new mud, trees back to full health with 4 fruit, only surviving scatterlings return, CheckRevive(), then the wave.
  • BuildWave: (4 + N) shamblers, N stalkers, 4 bad birds. Spawn times are spread evenly from 3 s to 48 s, with a little randomness.
  • EdgePos picks a border cell that is open and connected to the orchard (the reach grid).
  • EndNight: when the timer reaches 60 s and no ground enemy is left (or forced at 68 s). After night 13 you win; if every tree falls you lose.
Spawn time formula
ti=max(1,3+45·in−1+4(r−0.5))
n = events tonight, r = random 0..1. Then a StableSort by time.

Procedural map + BFS check

MapGenerator.cs
  • BuildStatic (once per game): about 10% hills, 8 bushes and 6 trees (at least 3 cells apart, not next to the centre).
  • ReachableStatic: a BFS flood fill from the centre (a Queue, 4 directions). Every tree must be reachable.
  • EdgesOpen: each side needs at least 3 reachable edge cells. TreesOpen: each tree needs at least 4 of its 8 neighbours open.
  • If a check fails, continue tries a new layout. If all pass, it saves a baseGrid snapshot. NewNightTerrain only adds new mud (10%) and branches each night.
// reject the layout until every check passes
if (!ReachableStatic(g, start, tc) || !EdgesOpen(g) || !TreesOpen(g, tc))
    continue;
Finish(g, tc, tries);   // baseGrid = grid.Clone()

Farmer, input and trees

TreeAndFarmer.cs · OrchardGame.cs (OnGUI, TrySwing, TryCatch)
  • OnGUI reads keyboard events, so it works with both the old and the new Input System. Held keys go in a HashSet.
  • Farmer.update: the WASD direction is normalised and multiplied by 165 px/s. If stun > 0, he only slides from the knockback and cannot be controlled.
  • TrySwing: 72 px range, an arc in front, 3.2 damage, and it sets e.lastHitByFarmer (used for the Shambler's grudge).
  • TreeEntity: gnaw(ps, dt) lowers health and heal raises it. firstHit remembers when it was first attacked (Pip's tie-break).
public void KnockBack(Pos from, double strength, double dazed) {
    double dx = x - from.x, dy = y - from.y, l = U.hypot(dx, dy);
    kbx = dx / l * strength;  kby = dy / l * strength;   // push away
    stun = dazed;                                        // 0.55 s no control
}

Steering and perception

AStar.cs · Steering, Perception
  • steer: works out the velocity needed to reach the target and blends the current velocity towards it (a smooth turn).
  • arrive: slows down inside the last slowR pixels, so there is no overshoot or jitter.
  • moveGround checks x and y separately, so walkers slide along walls. moveFree (dogs, birds, farmer) only keeps them on the board.
  • separate pushes enemies apart. slot gives each attacker a spot on its own side of the tree, so they form a ring.
  • LineOfSight samples the line every 5 px; if any point is on a HILL, the target is not visible.

A* pathfinding and Navigator

AStar.cs · FindPathToAny, Heap, Smooth, Navigator
  • 8 directions: diagonal steps cost √2, mud costs 3×, and no diagonal step cuts the corner of a hill or bush.
  • Octile heuristic (admissible). The open list is a hand-written binary min-heap, O(log n).
  • Multi-goal: it searches for many goals at once and returns the one that is cheapest to walk to.
  • Smooth (string pulling) keeps only the real turning points, checking a corridor as wide as the body.
  • Navigator re-plans every 0.3 to 0.6 s or when the goal changes. If the walker moves less than 4 px in 0.5 s, it is stuck and re-plans at once.
A* cost
f=g+1.0001·hh=max(Δx,Δy)+(2−1)min(Δx,Δy)
step=(1 or 2)×(3 if mud, else 1)
1.0001 is a tiny tie-break that keeps the search narrow on open ground.

Pip: Behaviour Tree

PipBehaviourTree.cs · BTNode, BTSelector, BTSequence, BTAction
  • A small hand-written BT framework: every node's Tick() returns Success, Failure or Running.
  • Selector returns the first child that does not fail. Sequence stops at the first child that does not succeed.
  • Branch 1, IsHurt: at hp ≤ 2.5 he runs to the farmer and heals 1.2 hp/s, and goes back to work at 4.5 (hysteresis).
  • Branch 2: HasDamagedTree → GoToTree (arrive) → RepairTree at 5 hp/s; he only leaves when the tree is full.
  • Branch 3, FollowFarmer: starts walking beyond 1.6 cells and stops inside 1 cell.
root = new BTSelector(new BTNode[] {
    new BTSequence(new BTNode[] { new BTAction(IsHurt), new BTAction(RetreatToFarmer) }),
    new BTSequence(new BTNode[] { new BTAction(HasDamagedTree),
                                  new BTAction(GoToTree), new BTAction(RepairTree) }),
    new BTAction(FollowFarmer)
});

Thistle: Finite State Machine

ThistleFSM.cs · enum ThistleState, update, near, Lead
  • enum ThistleState { Wander, Feed, Flee }. update() first checks the transitions, then runs the behaviour of the current state.
  • near() finds the most urgent ground enemy. One that is chewing a tree counts as 2.5 cells closer.
  • Feed: aims ahead of the target with Lead() (pursuit), then bites with target.hit(8·dt).
  • Only a Stalker bites back one-on-one (0.9 hp/s). Shamblers can only hurt her as a pack (card 11).

Shambler: Utility AI (desirability)

ShamblerUtilityAI.cs · Utility.Score, Shambler.Think, Do* actions · OrchardGame.PackBites
  • Think() runs every 0.25 s (with a random start so they do not all think on the same frame). It scores 5 options from 0 to 1.
  • Each score = weight × the product of its considerations, then a compensation step so options with more factors are not unfairly punished (Dave Mark's method).
  • The current action gets +0.12 (commitment), then the highest score wins. If the choice changes, nav.Reset() clears the old route.
  • Perception: it only knows about dogs and other Shamblers within 7 cells and in LineOfSight. Teamwork: Committed() reads the others' act and dogT.
  • update(): if the target has vanished it re-thinks at once, then runs DoRaid / DoEat / DoPack / DoHitFarmer / DoFlee. If the straight line is clear it steers; otherwise it uses A* (GoTo).
  • The pack rule lives in the game class: damage only happens when PackSize(dog) ≥ 2. A lone Shambler can bite, but it does no harm.
// multiply considerations, then correct for how many there are
public static double Score(double weight, params double[] cons) {
    double s = 1;
    foreach (double c in cons) s *= Clamp01(c);
    int n = cons.Length;
    if (n > 1 && s > 0) s = s + (1 - s) * (1.0 - 1.0 / n) * s;
    return weight * s;
}
// pick: commitment bonus, then argmax
double[] s2 = (double[])scores.Clone();
s2[(int)act] += 0.12;
int best = 0;  for (int i = 1; i < 5; i++) if (s2[i] > s2[best]) best = i;

Stalker: perception

Enemies.cs · Stalker.InView, update, Go
  • InView: the angle to the farmer minus face must be within ±70° (a 140° cone). Within 1.5 cells he is always sensed.
  • Once the farmer is seen, the range grows to 1.2× and the cone is no longer needed (hysteresis).
  • When sight is lost it stores lastSeen and has 3 s of memory: it walks there and looks around.
  • It keeps a smoothed estimate of the farmer's velocity and aims ahead of him (lead). With nothing to chase, it chews a tree (9 hp/s).
Sight + lead
|θ−φ|≤70∘τ=min(0.6,d1.1s)aim=pfarmer+v^τ
v̂ = the velocity estimate, smoothed each frame with k = min(1, 6Δt).

Birds: Boids flocking

Enemies.cs · Bird.update, nearBait
  • Looks at birds of the same type within 3 cells, ignoring those right behind (field of view).
  • Separation (closer birds push harder), alignment (match heading), cohesion (move to the group centre).
  • Goal: fallen fruit (nearBait skips fruit another bird has claimed, so the flock spreads out). With no fruit, they roam the sky.
  • Black birds use pursuit on scatterlings, catch within 0.55 cells, then rest 10 s. Yellow birds use predator avoidance. Soft walls turn them before the edge.
Force sum (weights from the code)
F=1.6S+0.9A+0.7C+1.6G+1.5P+3.2Eavoid+2.5W
v←v+(F‖F‖−v)min(1,6Δt)
P is for black birds only; Eavoid is for yellow birds only. Speed: yellow 132, black 118 px/s.

Fruit economy and revive

OrchardGame.cs · TryCatch, flyingFruit, baits, CheckRevive, BirdCaught
  • Pluck (F near a tree): the fruit becomes a FlyingFruit in the air. Catch it and it is saved; after 2.4 s it lands as Bait.
  • If a yellow bird eats the bait it is saved (birdSaved++); a black bird means lost; a Shambler gains 3 hp.
  • CheckRevive: while the bank is at least 200, the tree that fell first comes back (golden glow).
  • BirdCaught: a caught scatterling becomes a FallenBird, drops and lands on its back. It is not replaced.
Revive bank
bank=Fbirds−200·Rbank≥200⇒revive
Fbirds = fruit saved by scatterlings, R = revives so far.

GameRenderer: board drawing

GameRenderer.cs · Render, Resize, Shapes
  • A separate orthographic camera sees only layer 31 and draws into a RenderTexture (4× MSAA).
  • Immediate-mode style: each frame reuses a SpriteRenderer pool instead of creating new objects.
  • Depth sort by y (StableSort): things lower on screen are drawn in front (painter's algorithm).
  • Resize makes the texture the same size as the board's real pixels on screen, so it stays sharp on Retina.
  • Effects: rain, fog, fireflies, night darkness with the farmer's lantern, and AI debug visuals (pack lines, intent bubbles, Tab bars).
// render the board at exactly the pixels it covers on screen
public bool Resize(int w, int h) {
    if (rt != null && rt.width == w && rt.height == h) return false;
    RenderTexture old = rt;
    rt = MakeRT(w, h);  cam.targetTexture = rt;
    if (old != null) { old.Release(); Object.Destroy(old); }
    return true;
}

Editor helpers

Testing: headless runs without Unity

Harness.cs + Stubs.cs (test tools, not part of the project)
  • Stubs.cs is a small fake version of Unity (Color, Mathf, MonoBehaviour, Texture...) so the game scripts compile with the Mono mcs compiler.
  • Harness.cs puts a seeded random generator into U.rng (using reflection), then runs UpdateGame at 60 fps. A scripted farmer walks with WASD, swings every 20 frames and tries to catch every 7 frames.
  • Each frame it counts every Shambler's act, and it counts log lines: pack formed, fled, ate, hit the farmer, tree fell.
  • The numbers guided the balance: the first version was too hard (about night 6), so health, ranges, weights, Thistle's bite (8/s) and MAX_HP (6) were tuned.
  • Visual check: draw calls were recorded and replayed in Playwright to get screenshots without Unity.

Key takeaways

  1. One MonoBehaviour, the rest is plain C#: OrchardBoot creates the game itself, with no scene or prefab setup.
  2. Logic and drawing are separate: UpdateGame only changes state; GameRenderer and OrchardUI only read it. This made headless testing possible.
  3. Each agent has its own technique and file: Pip = Behaviour Tree, Thistle = FSM, Shambler = Utility AI, Stalker = Perception, Birds = Boids.
  4. Shared building blocks: all ground enemies use A*, Navigator and Steering; both the Stalker and the Shambler use LineOfSight.
  5. Agents read each other: a Shambler checks other Shamblers' act and what Pip and Thistle are targeting; Thistle goes for tree-chewers first; Pip picks the weakest tree.
  6. Hysteresis everywhere: Pip 2.5/4.5 hp, Thistle 6/7.5 cells, Stalker 1.2× sight, Shambler +0.12 commitment. This stops any agent from flickering between choices.
  7. The numbers come from testing: balance was tuned with seeded headless games, not guesswork.
